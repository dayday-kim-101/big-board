# 주식 전광판 (Stock Big Board) — 요구사항

- **작성일**: 2026-05-31
- **상태**: 브레인스토밍 완료 → 플래닝 대기
- **유형**: 신규 제품 (greenfield, `prj-bigboard`)

## 한 줄 요약

키움 HTS 전광판 스타일의 **개인용 주식 종목판 웹사이트**. 이메일만 입력하면 어디서든 접속해, 내가 정리한 한국·미국 종목들의 가격 스냅샷을 격자로 본다. 최대 5명이 각자 자기 종목판을 갖고, 완전 무료로 운영한다.

## 배경 / 동기

- 키움 HTS의 전광판은 Windows 데스크톱 앱에 묶여 있어 **폰·외부 PC 등 어디서나** 보기 어렵다.
- 원하는 것은 "내 관심 종목을 시장(KR/US)·그룹별로 정리해 한눈에 보는 보드"이며, 실시간 매매가 아니라 **가격 확인·정리** 용도다.
- 본인을 포함한 소수(최대 5명)가 각자 자기 목록을 갖고 가볍게 쓰는 것이 목표.

## 사용자

- **주 사용자**: 본인(소유자) — 자기 종목판을 직접 추가·정리.
- **부가 사용자**: 신뢰하는 지인 최대 4명 — 각자 자기 이메일로 자기 종목판을 갖고 편집.
- 총 **동시 최대 5명**, 모두 신뢰 그룹.

## 목표 / 성공 기준

1. 이메일 입력만으로 어떤 기기·장소에서든 내 종목판이 로드된다.
2. 종목을 추가/삭제하고 그룹·탭으로 분류해 정리할 수 있다.
3. 각 종목의 **종목명·현재가·등락폭·등락률·거래량·거래대금**이 전광판 격자로 보인다.
4. 한 기기에서 편집한 목록이 다른 기기에서도 그대로 동기화된다.
5. 운영 비용 **0원**, 5명 동시 접속에도 안정적.
6. 가격은 수동 새로고침 + 주기적 자동 스냅샷으로 갱신된다(실시간 아님).

## 범위 (In Scope)

- **이메일 기반 접속**: 비밀번호 없이 이메일을 식별 키로 사용해 해당 종목판을 로드.
- **종목 관리**: 한국(KOSPI/KOSDAQ)·미국 종목 추가·삭제.
- **정리(그룹/탭)**: 사용자가 만든 그룹·탭(예: "관심", "보유", "반도체")으로 종목 분류. 시장(KR/US) 구분 포함.
- **전광판 표시**: 종목명, 현재가, 등락폭, 등락률(%), 거래량, 거래대금. 한국식 색 관례(상승 🔴 빨강 / 하락 🔵 파랑).
- **가격 갱신**: 수동 새로고침 버튼 + 주기적 자동 스냅샷.
- **크로스 디바이스 동기화**: 폰·PC 어디서 편집해도 목록·그룹이 따라옴.

## 범위 밖 (Out of Scope)

- 실시간 체결가(틱 단위 갱신), 호가창.
- 차트, 기술적 지표, 뉴스.
- 실제 매매/주문 기능.
- 비밀번호·OAuth 등 본격 인증.

## 보류 (Deferred — 나중에 추가 가능)

- 정렬(등락률·거래량 기준)·필터(상승만 보기 등). 1차 범위에서 제외, 그룹/탭이 자리 잡은 뒤 검토.
- 이메일 약점 보완(예: 간단한 PIN, 매직링크).
- 52주 고저점 등 추가 상세 지표.

## 핵심 결정 사항

| 결정 | 선택 | 근거 |
|---|---|---|
| 가격 실시간성 | **수동/주기적 스냅샷** | 가장 단순·안정·무료. "관리 쉬움" 목표에 부합 |
| 사용자 모델 | **각자 자기 종목판** | 이메일이 목록 라우팅 키 |
| 편집·동기화 | **각자 편집 + 어디서든 동기화** | 작은 무료 서버 함수 1개 채택으로 실현 |
| 표시 항목 | 종목명·현재가·등락폭·등락률·거래량·거래대금 | 사용자 선택 |
| 정리 방식 | **그룹/탭 분류** | 한 줄 목록보다 강력, 정렬·필터보다 단순한 중간값 |
| 색 관례 | 한국식(상승 빨강/하락 파랑) | 한국형 전광판. KR/US 공통 적용(기본값) |
| 한국 데이터 소스 | **Yahoo + 네이버 (계좌 불필요)** | 증권 계좌 개설 마찰 회피 우선 |

## 아키텍처 방향 (이 브레인스토밍이 기술 결정 자체였으므로 기록)

> 상세 설계(파일 구조, 스키마, 엔드포인트, 배포 토폴로지)는 플래닝 단계의 몫.

- **프론트엔드**: 정적 사이트 (GitHub Pages 또는 Cloudflare Pages).
- **백엔드**: 작은 무료 서버 함수 **1개** (Cloudflare Workers 무료 티어 권장).
  - 역할 ①: GitHub 쓰기용 토큰을 서버 쪽에 은닉(공개 사이트에 토큰 노출 방지).
  - 역할 ②: 외부 주가 API 호출 프록시 — CORS 우회 + 비공식 엔드포인트 IP 분산.
- **데이터 저장**: GitHub 저장소의 **이메일별 JSON/텍스트 파일**. 별도 DB 없음. (사용자의 "GitHub으로 데이터 관리" 요구 충족)
- **주가 데이터**:
  - 미국 + 한국 가격·등락·등락률·거래량 → **Yahoo Finance** 비공식 엔드포인트(한국주는 `.KS`/`.KQ` 접미사), Worker가 서버에서 호출.
  - 한국 **거래대금** → Yahoo에 없으므로 **네이버 금융** 엔드포인트를 Worker가 추가 호출.
- **자동 스냅샷**: 주기적 갱신은 Worker cron 또는 GitHub Action(스케줄) 중 택일 — 플래닝에서 결정.

## 가정 / 리스크

1. **한국 데이터 소스(Yahoo/네이버)가 비공식·약관 회색지대** — 구조 변경 시 깨질 수 있고, 과도한 폴링 시 IP 차단 가능. 5명·저빈도 폴링이라 위험은 낮지만 실재함. 깨질 경우 대안: 증권사 Open API(KIS/키움, 계좌 필요)로 전환.
   - *플래닝 시 확인*: Yahoo `query1` 엔드포인트와 네이버 금융 응답 포맷의 현재 동작 검증, Worker IP에서의 호출 성공 여부.
2. **이메일 인증이 약함(비밀번호 없음)** — 남의 이메일을 알면 그 사람 목록을 보고 편집할 수 있음. 5명 신뢰 그룹 전제로 수용. 필요 시 보류 항목의 PIN/매직링크로 보완.
3. **거래대금은 한국 종목 1개당 네이버 호출이 추가**되어 호출 수가 늘어남 — 종목 수 한도/캐싱 전략을 플래닝에서 고려.

## 미해결 질문 (플래닝에서 결정)

- 정적 호스팅을 GitHub Pages로 할지, 프론트+Worker를 한 계정에 묶기 위해 Cloudflare Pages로 할지.
- 주기적 스냅샷 주기(예: 장중 N분)와 실행 주체(Worker cron vs GitHub Action).
- 이메일별 파일 구조와 동시 편집 충돌 처리(5명이라 거의 무충돌이나 정의 필요).
- 미국 거래대금 표시 여부(Yahoo 미제공 → `가격 × 거래량`으로 근사할지).
